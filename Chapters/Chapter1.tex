\section{Parametric Models and Gradient-Based Optimization}

The majority of machine learning models can be seen as \textbf{Parametric Models}. A parametric model takes an input $x$ and uses a set of parameters (or weights) $W$ and biases $b$ to produce an output prediction $z$:
\[ z = f(x,W) = Wx + b \]

While the exact nature of the prediction depends on the task, what unifies these models is the \textbf{Optimization Process}. We define a Loss function $L$ that measures the error of our predictions, and we iteratively adjust the weights using \textbf{Gradient Descent}:
\[ W^{t+1} = W^t - \alpha \nabla_W L \]
where $\alpha$ is the learning rate.

By simply changing the \textit{activation function} applied to the linear score $z$ and the corresponding \textit{loss function}, we obtain different classical models: Linear Regression, Logistic Regression, and the Softmax Classifier.

\subsection{Linear Regression (\texorpdfstring{$f: \mathbb{R}^D \to \mathbb{R}$}{R -> R})}
Linear Regression is used when the target variable is continuous. We use the identity activation function (i.e., no activation), so the predicted output $\hat{y}$ is exactly the linear score:
\[ \hat{y} = z = Wx + b \]
We optimize this model by minimizing the \textbf{Mean Squared Error (MSE)} loss:
\[ L = \frac{1}{N} \sum_{i=1}^N {(y_i - \hat{y}_i)}^2 \]

\subsection{Logistic Regression (\texorpdfstring{$f: \mathbb{R}^D \to [0, 1]$}{R -> [0, 1]})}
Logistic Regression is used for binary classification. We map the linear score $z$ to a probability between 0 and 1 using the \textbf{Sigmoid} activation function $\sigma(z)$:
\[ P(Y=1 | X=x) = \sigma(z) = \frac{1}{1 + e^{-z}} \]
The appropriate loss function for this model is the \textbf{Binary Cross-Entropy Loss (BCE)}. For a dataset of $N$ samples, it is defined as:
\[ L = -\frac{1}{N} \sum_{i=1}^N \left[ \underbrace{y_i \log(\sigma(z_i))}_{\text{Active if } y=1} + \underbrace{(1 - y_i) \log(1 - \sigma(z_i))}_{\text{Active if } y=0} \right] \]

\begin{Notebox}
\textbf{Understanding the BCE Formula:} This equation uses a clever mathematical trick to combine two mutually exclusive cases into a single line:
\begin{itemize}[nosep, leftmargin=*]
    \item When the true class is \textbf{$y_i = 1$}, the second term $(1 - 1) = 0$ disappears, and the loss evaluates only $-\log(\sigma(z_i))$, penalizing the model if it predicts a low probability.
    \item When the true class is \textbf{$y_i = 0$}, the first term $0$ disappears, and the loss evaluates only $-\log(1 - \sigma(z_i))$, penalizing the model if it predicts a high probability for class 1.
\end{itemize}
\end{Notebox}

    \centering
    \includegraphics[width=0.7\textwidth]{Pictures/logistic.png}
    \caption{Illustration of the Sigmoid function in Logistic Regression.}\label{fig:logisticregresssion}
\end{figure}

\subsection{Softmax Classifier (\texorpdfstring{$f: \mathbb{R}^D \to \{0, \dots, K\}$}{R -> \{0, \dots, K\}})}
The Softmax Classifier generalizes Logistic Regression to multiple, mutually exclusive classes. It maps the raw scores $z$ into a valid probability distribution over the classes using the \textbf{Softmax function}:
\[ P(Y = k | X = x_i) = \frac{e^{z_k}}{\sum_j e^{z_j}} \]

\begin{Notebox}
\textbf{Why Softmax?} We want to interpret raw classifier scores as \textit{probabilities}. The Softmax function transforms scores such that they are strictly positive and sum to 1.
\end{Notebox}

\begin{examplebox}
For an input image of size $32 \times 32 \times 3$ (e.g., CIFAR-10), the flattened array $x$ has $3072$ numbers. If we are classifying into 10 categories, the weight matrix $W$ will have dimensions $10 \times 3072$, producing a $10 \times 1$ vector of raw class scores before the Softmax is applied.
\end{examplebox}

We then optimize the model using the \textbf{Categorical Cross-Entropy Loss}, often referred to as the Negative Log-Likelihood (NLL). Over the entire dataset of $N$ samples, expanding the Softmax probability formula, the loss becomes:
\[ NLL(W, X) = -\sum_{i=1}^N \left[ \underbrace{W_{y_i}^T x_i}_{\text{Punteggio della classe giusta}} - \underbrace{\log \left( \sum_{k=1}^K \exp(W_k^T x_i) \right)}_{\text{Somma dei punteggi delle altre classi}} \right] \]

\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.7\textwidth]{Pictures/softmax.png}
    \caption{Abstract representation of logistic regression.}\label{fig:Softmax}
\end{figure}

\begin{Notebox}
\textbf{Understanding the Softmax NLL Formula:} 
By looking at the expanded formula, we see that the optimizer tries to maximize the linear score $W_{y_i}^T x_i$ of the \textit{correct class} $y_i$, while simultaneously pushing down the log-sum of the scores of \textit{all available classes}. This creates a competitive environment where increasing the score of the correct class implicitly decreases the relative probability of the others.
\end{Notebox}

\section{Advanced Optimization and Regularization}

\subsection{Regularization}
The primary goal of Regularization is to prevent the model from becoming too complex and overfitting the training data (i.e., we use it to combat \textbf{High Variance}). We achieve this by adding a penalty term $R(W)$, based only on the model's parameters, directly to the Data Loss. 

The new Total Loss becomes:
\[ L_{total}(W, X) = \underbrace{L(W, X)}_{\text{Data Loss}} + \underbrace{\lambda R(W)}_{\text{Regularization Term}} \]

\begin{Notebox}
\textbf{When and how is it applied?}\\
Regularization is applied \textit{during training}. By redefining the Total Loss, we also change its gradient. When we apply Gradient Descent, the algorithm must now minimize both the data error AND the complexity of the weights. For example, the gradient of an L2 penalty $\lambda W^2$ is $2\lambda W$, meaning Gradient Descent will actively shrink the weights at every step (Weight Decay).
\end{Notebox}

The hyperparameter $\lambda$ acts as the ``manipulator'' of complexity:
\begin{itemize}[nosep, leftmargin=*]
    \item $\lambda = 0$: We ignore complexity. The model relies entirely on Data Loss (Risk of \textbf{Overfitting}).
    \item $\lambda \to \infty$: The model becomes ``lazy''. The penalty is so high that Gradient Descent brings all weights to zero (Risk of \textbf{Underfitting}).
\end{itemize}

The two most classic mathematical formulations are:
\begin{itemize}[nosep, leftmargin=*]
    \item \textbf{L2 Regularization (Ridge):} $R(W) = \sum W^2$. It punishes larger weights more severely, forcing the network to distribute the ``weight'' across all features rather than relying heavily on just a few. It shrinks weights but rarely brings them exactly to zero.
    \item \textbf{L1 Regularization (Lasso):} $R(W) = \sum |W|$. It punishes weights constantly. This has the mathematical effect of bringing less important weights exactly to zero, acting as an automatic \textit{Feature Selection} mechanism.
\end{itemize}

While L1 and L2 regularization act directly on the loss function, modern Deep Learning heavily relies on \textit{architectural} and \textit{stochastic} regularization techniques.

\subsection{Dropout}
\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.7\textwidth]{Pictures/dropout.png}\label{fig:dropout}
\end{figure}
First introduced by Srivastava et al. (2014), \textbf{Dropout} is a simple yet incredibly effective regularization technique for neural networks.
\\
\textbf{How it works:} During training (in each forward pass), we randomly set a fraction of neurons to zero. The probability of dropping a neuron is a hyperparameter, with $p=0.5$ being a common default for fully connected layers.

\begin{itemize}[nosep, leftmargin=*]
    \item \textbf{Why does it work?} 
    \begin{enumerate}
        \item \textbf{Prevents Co-adaptation:} It forces the network to learn a \textit{redundant representation}. If a neuron cannot rely on the presence of specific other neurons, it must learn robust, independent features (e.g., detecting a cat's ear rather than memorizing the whole cat's face).
        \item \textbf{Ensemble Interpretation:} Dropout can be seen as training a massive ensemble of sub-networks that share parameters. An FC layer with 4096 units has $2^{4096}$ possible binary masks (sub-models)!
    \end{enumerate}
\end{itemize}


\subsubsection{The Solution: Inverted Dropout}
Dropping neurons only during \textit{training} means that at \textit{test time} (when all neurons are active), the total output sum will be \textbf{much larger}. For example, if $p=0.5$ (Dropout Rate), the expected output at test time is twice as large. Instead of modifying the network at test time, we apply a \"correction\" directly during training. We define the training activation $h$ as:
\[ h_{\text{train}} = \frac{\text{mask} \odot x}{1-p} \]
Let's break down exactly what this formula does:
\begin{itemize}[leftmargin=*]
    \item \textbf{The Numerator} ($\text{mask} \odot x$): This is the actual dropout operation. The \texttt{mask} is a matrix of $0$s and $1$s (where a $0$ appears with probability $p$). By performing element-wise multiplication ($\odot$), we force a fraction $p$ of the activations in $x$ to become exactly zero, effectively \"turning off\" those neurons for the current pass.
    \item \textbf{The Denominator} ($1-p$) \textbf{Pumping part}: This is the \"keep probability\" scaling factor. Since we turned off a fraction $p$ of the neurons, the total sum of the layer's output dropped. By dividing the \textit{surviving} neurons by $(1-p)$, we artificially inflate their values. This mathematically guarantees that the \textit{expected value} of the layer remains identical to what it will be at test time.
\end{itemize}

Thanks to this trick, at test time the network requires no scaling at all, running at maximum efficiency:
\[ h_{\text{test}} = x \]

\begin{examplebox}
\textbf{Numerical Example of Inverted Dropout ($p=0.5$)}

Given an input $x = [10, 20, 30, 40]$ (Sum $= 100$) and dropout rate $p=0.5$:

\textbf{1. Generate Binary Mask:} 
Random mask with $50\%$ probability of being $0$.
\[ \text{mask} = [1, 0, 1, 0] \]

\textbf{2. Apply Numerator (Masking):} 
Element-wise multiplication drops the 2nd and 4th neurons (Sum drops to $40$).
\[ \text{mask} \odot x = [1, 0, 1, 0] \odot [10, 20, 30, 40] = [10, 0, 30, 0] \]

\textbf{3. Apply Denominator (Scaling):} 
Divide by $(1-p) = 0.5$ to inflate surviving neurons, restoring signal energy (Sum becomes $80 \approx 100$).
\[ h_{\text{train}} = \frac{[10, 0, 30, 0]}{0.5} = [20, 0, 60, 0] \]
\end{examplebox}



\subsection{The Common Pattern of Modern Regularization}
Dropout is just one example of a broader paradigm in deep learning regularization. The general framework is:
\begin{enumerate}
    \item \textbf{Training:} Add some kind of randomness or noise.
    \item \textbf{Testing:} Average out (or marginalize) the randomness to produce a deterministic prediction.
\end{enumerate}

Other notable examples following this pattern include:
\begin{itemize}[nosep, leftmargin=*]
    \item \textbf{Batch Normalization:} Injects randomness during training because a sample's normalization depends on the random composition of its minibatch. At test time, global running statistics are used instead.
\end{itemize}

\subsection{Data Augmentation (and Advanced Image Regularization)}
While L1/L2 act on the network's weights and Dropout acts on the activations, Data Augmentation acts directly on the input data. It is a powerful regularization technique that artificially expands the training dataset by applying label-preserving transformations.
This perfectly embodies the ``Common Pattern'' of modern regularization: we introduce heavy randomness during training, and we average it out (or use fixed standard inputs) during testing.

\subsubsection{Classic Spatial and Color Augmentations}
\begin{itemize}[leftmargin=*]
    \item \textbf{Horizontal Flips:} A simple but highly effective transformation for most general object recognition tasks.
    \item \textbf{Random Crops and Scales:} During training, we extract random patches at random scales. For instance, ResNet resizes the image so its short side is a random length between 256 and 480, then takes a random $224 \times 224$ crop. At test time, this randomness is marginalized by evaluating a fixed set of crops (e.g., 10 crops: 4 corners + center, and their horizontal flips) and averaging the predictions.
    \item \textbf{Color Jitter:} Randomizing contrast and brightness to make the model invariant to lighting conditions. More complex variants apply PCA to the RGB channels of the training set, adding random offsets along the principal components.
\end{itemize}

\subsubsection{Advanced Stochastic Augmentations}
\begin{itemize}[leftmargin=*]
    \item \textbf{Cutout:} During training, we randomly mask out (set to zero) square regions of the input image. This prevents the network from relying exclusively on a single dominant visual feature (like an animal's face) and forces it to utilize the broader context. At test time, the full unmodified image is used.
    \item \textbf{Mixup (Zhang et al., 2018):} Instead of modifying a single image, Mixup blends pairs of images and their corresponding labels. If we blend $40\%$ of a cat image and $60\%$ of a dog image, the new target label fed to the loss function becomes exactly \texttt{[0.4 cat, 0.6 dog]}. Testing is performed on standard, unblended images.
\end{itemize}

\subsection{Stochastic Gradient Descent (SGD)}
From a theoretical standpoint, our objective is to minimize the total loss over the entire dataset, which includes both the data loss and the regularization term:
\[ L(W) = \frac{1}{N} \sum_{i=1}^N L_i(x_i, y_i, W) + \lambda R(W) \]
To update the weights, we need the exact gradient of this total loss:
\[ \nabla_W L(W) = \frac{1}{N} \sum_{i=1}^N \nabla_W L_i(x_i, y_i, W) + \lambda \nabla_W R(W) \]

Computing this true gradient (the \textbf{Full Batch} gradient) requires evaluating the sum over all $N$ samples in the dataset at every single step. When $N$ is in the millions, this becomes computationally unfeasible.

\begin{keywordbox}
\textbf{Stochastic Gradient Descent (SGD):} Instead of the full sum, SGD approximates the true gradient by computing the sum over a small \textbf{minibatch} of examples (commonly 32, 64, or 128). This introduces noise but allows for much faster and frequent parameter updates.
\end{keywordbox}

\section{Backpropagation and Neural Networks}

\subsection{Backpropagation}
To update weights, we compute gradients via \textbf{Backpropagation}, which applies the chain rule from the output back to the inputs (backward pass).

\begin{Notebox}
\textbf{Backprop with Matrices:} When inputs and weights are vectors or matrices, local gradients become \textit{Jacobian matrices}. However, Jacobians are often sparse. Instead of explicitly forming them, we use implicit multiplication. A very useful trick to remember: the downstream gradient $dL/dx$ \textbf{always has the same shape} as $x$!
\end{Notebox}

\section{The Role of Activation Functions}

An \textbf{activation function} is a mathematical ``gate'' applied to the output of a layer ($z = Wx+b$) before passing it to the next layer. Its primary role is to introduce \textbf{non-linearity} into the network. 

\begin{Notebox}
\textbf{Why do we need Non-Linearity?} If we only stacked linear layers without activation functions, the entire deep network would mathematically collapse into a single linear transformation. For example, a 2-layer linear network $f = W_2(W_1 x)$ can be rewritten as $f = W'x$ where $W' = W_2 W_1$. Non-linear activations allow the network to learn and approximate highly complex, non-linear boundaries.
\end{Notebox}

\subsection{1. ReLU (Rectified Linear Unit)}
\textbf{Formula:} $f(x) = \max(0, x)$ \\
ReLU is the most widely used default activation function in Deep Learning.
\begin{itemize}[nosep, leftmargin=*]
    \item \textbf{Pros:} It does not saturate in the positive region. It is highly computationally efficient (just a thresholding operation) and converges much faster than Sigmoid/Tanh in practice (e.g., roughly $6\times$ faster).
    \item \textbf{Cons:} Its outputs are not zero-centered. Most importantly, it suffers from the \textbf{``Dead ReLU''} problem: if $x < 0$, the gradient is exactly $0$. If a neuron is pushed into the negative regime by a large weight update, its weights will never update again.
\end{itemize}

\subsection{2. Leaky ReLU}
\textbf{Formula:} $f(x) = \max(\alpha x, x)$ (where typically $\alpha = 0.01$) \\
Designed to solve the ``dead neuron'' problem of standard ReLU.\
\begin{itemize}[nosep, leftmargin=*]
    \item \textbf{Pros:} Retains all the benefits of ReLU (no positive saturation, computationally efficient, fast convergence), but the small non-zero slope for negative inputs ensures the neurons will not ``die''.
\end{itemize}

\subsection{3. ELU (Exponential Linear Units)}
\textbf{Formula:} $f(x) = x$ if $x > 0$, else $\alpha(e^x - 1)$
\begin{itemize}[nosep, leftmargin=*]
    \item \textbf{Pros:} Has all the benefits of ReLU, but produces outputs that are closer to zero-mean. Furthermore, its negative saturation regime adds some robustness to noise compared to the unbounded negative regime of Leaky ReLU.\
    \item \textbf{Cons:} Computation is more expensive because it requires evaluating the exponential function $e^x$.
\end{itemize}

\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.4\textwidth]{Pictures/Elu.png}
    \caption{Illustration of a ELU}\label{fig:Elu}
\end{figure}

\subsection{4. GELU (Gaussian Error Linear Unit)}
\textbf{Formula:} $f(x) = x \cdot \Phi(x)$, where $\Phi(x)$ is the cumulative distribution function (CDF) of the standard normal distribution.
\begin{itemize}[nosep, leftmargin=*]
    \item \textbf{Pros:} Exhibits very nice behavior around $0$. Its mathematical smoothness facilitates training in practice. It is widely used in state-of-the-art models like \textbf{GPT-3, BERT}, and most other Transformers.
    \item \textbf{Cons:} Higher computational cost than ReLU.\ Note that for large negative values, the gradient still tends to $0$.
\end{itemize}

\begin{Notebox}
\textbf{TL;DR \- Practical Guidelines for Activation Functions:}
\begin{itemize}[nosep, leftmargin=*]
    \item Use \textbf{ReLU} as your standard default, but be careful with your learning rates to avoid dead neurons.
    \item Try out \textbf{Leaky ReLU}, \textbf{PReLU} (Parametric ReLU), or \textbf{GELU} to squeeze out some marginal performance gains.
    \item Generally avoid \textbf{Sigmoid/Tanh} for hidden layers unless specifically required by the architecture (e.g., LSTM gates).
\end{itemize}
\end{Notebox}

\section{Weight Initialization}

Properly initializing the weights of a neural network is crucial. If the initialization is poor, the network might not learn at all due to exploding or vanishing gradients.

\subsection{The Pitfalls of Naive Initialization}
\begin{itemize}[nosep, leftmargin=*]
    \item \textbf{Constant Initialization ($W = \text{constant}$):} If all weights are initialized to the same value (e.g., $W=0$), every neuron in a layer will compute the exact same output. During backpropagation, they will all receive the exact same gradient and undergo the exact same update. The network fails to \textit{break symmetry} and cannot learn independent features.
\end{itemize}

\subsubsection*{Small Random Noise and Vanishing Gradients}
A common naive approach is to initialize weights with very small random numbers. If you look closely at the code snippet in the image below, you'll see the line \texttt{W = 0.01 * np.random.randn(D,H)}. The function \texttt{np.random.randn(D,H)} (where \texttt{D} is $D_{in}$ and \texttt{H} is $D_{out}$) does not generate a single random number; it generates a \textbf{weight matrix} of dimensions $D_{in} \times D_{out}$. Every element in this matrix is randomly sampled from a standard normal distribution (mean 0, variance 1). By multiplying this entire matrix by the scalar $0.01$, we scale all the initial weights so they have a very small standard deviation of $0.01$. % chktex 36

To understand why this fails in deep networks, we must separate what happens during the Forward Pass from what happens during the Backward Pass:

\begin{figure}[htbp]
    \centering
    \includegraphics[width=1\textwidth]{Pictures/activation_stats.png}
    \caption{Distribution of activations $x$ across 6 layers with $W \sim \mathcal{N}(0, 0.01)$ and Tanh.}\label{fig:activation_stats}
\end{figure}

\begin{itemize}[leftmargin=*]
    \item \textbf{Step 1: The Forward Pass (Shrinking Activations).}\\
    The histograms above do \textit{not} show the weights; they show the \textbf{activations} (the input $x$ of each layer). In a neural network, the output of a layer is roughly the input $x$ multiplied by the weights $W$. Because the weights $W$ are tiny fractions (scaled by $0.01$), the resulting output will be strictly smaller than the input. 
    Since the network is sequential, this effect compounds: you multiply by a tiny $W$, then the next layer multiplies that result by another tiny $W$. This repeated multiplication causes the signal $x$ to exponentially decay. As seen in the histograms, Layer 1 starts with a healthy spread (std = 0.49), but by Layer 6, the activations $x$ have completely collapsed to $0$ (std = 0.05).
    
    \item \textbf{Step 2: The Backward Pass (Vanishing Gradients).}\\
    Why does this destroy learning? Recall the backpropagation formula. For a simple linear layer $y = Wx$, the local gradient of the weights is $\frac{\partial y}{\partial W} = x$. Applying the chain rule, the gradient of the Loss $L$ with respect to the weights $W$ is:
    \[ \frac{\partial L}{\partial W} = x^T \frac{\partial L}{\partial y} \]
    The critical insight here is that \textbf{the weight update is directly proportional to the input activations $x$}. Because the forward pass (Step 1) caused the activations $x$ to become $0$, the formula becomes $\frac{\partial L}{\partial W} = 0 \cdot \frac{\partial L}{\partial y} = 0$. The network stops updating its weights, resulting in the \textbf{Vanishing Gradient} problem.
\end{itemize}

\subsection{Variance Scaling Methods: The Solution}
To ensure that all neurons start from different states and that the signal flows correctly without vanishing or exploding, we must stop using a fixed, naive scalar like $0.01$. Instead, we scale the initial random weights \textbf{dynamically}, based on the number of inputs ($D_{in}$) a neuron receives. 

By replacing the fixed $0.01$ scalar with a dynamically calculated standard deviation (\text{std}), we can keep the variance of the activations stable across all layers.

\begin{keywordbox}
\textbf{1. Xavier (Glorot) Initialization}\\
Designed for symmetric activation functions like \textbf{Tanh} or \textbf{Sigmoid}. The goal is to keep the variance of the activations constant across layers. Weights are sampled from a distribution with standard deviation:
\[ \text{std} = \frac{1}{\sqrt{D_{in}}} \]

\textbf{2. Kaiming (He) Initialization}\\
Xavier initialization fails when using \textbf{ReLU}, because ReLU zeroes out exactly half of the output distribution (all negative values), effectively halving the variance. Kaiming initialization corrects this by multiplying the variance by $2$, yielding a standard deviation of:
\[ \text{std} = \sqrt{\frac{2}{D_{in}}} \]
This is the standard and highly recommended initialization whenever you use ReLU or Leaky ReLU\@.
\end{keywordbox}

\textit{Note: For Convolutional Layers, the number of inputs $D_{in}$ is calculated as $\text{kernel\_size}^2 \times \text{input\_channels}$.}




























\section{Batch Normalization}

\subsection{The Problem and Basic Intuition}
The core idea behind Batch Normalization (BN) is simple: if we want our activations to have zero mean\ref{fig:activation_stats} and unit variance to facilitate training, we can simply apply a differentiable function that forces the data into this distribution.
To achieve this, the layer takes a minibatch of data as input and computes the mean and variance separately for each dimension (or channel) $k$, then normalizes the values using this formula:

\[ \widehat{x}^{(k)} = \frac{x^{(k)} - \text{E}[x^{(k)}]}{\sqrt{\text{Var}[x^{(k)}]}} \]

Let's analyze each component of the formula:
\begin{itemize}[nosep, leftmargin=*]
    \item $x^{(k)}$: The activation value for the $k$-th dimension (or channel) of our current input, before normalization.
    \item $\text{E}[x^{(k)}]$: The \textit{expected value} (i.e., the \textbf{mean} $\mu$) computed along dimension $k$ over all elements in the current minibatch.
    \item $\text{Var}[x^{(k)}]$: The \textbf{variance} ($\sigma^2$) computed along dimension $k$ over the entire minibatch. The square root of the variance gives us the standard deviation. \textit{(Note: in practice, a tiny value $\epsilon$ is often added to the variance inside the square root to avoid division by zero).}
    \item $\widehat{x}^{(k)}$: The new normalized value, which now belongs to a distribution with a mean of 0 and a variance of 1.
\end{itemize}

\subsection{Learnable Parameters (Scale and Shift)}
Strictly forcing the data to have a mean of 0 and a variance of 1 might prove to be too rigid of a constraint, limiting the expressive power of the network. 
To solve this problem, immediately after normalization, two parameters are applied that the network learns during training: $\gamma$ (for scale) and $\beta$ (for shift). The final output of the layer thus becomes:
\[ y^{(k)} = \gamma^{(k)} \widehat{x}^{(k)} + \beta^{(k)} \]

This step guarantees flexibility: if the network learns that strict normalization at that specific point is counterproductive, it can learn to set the weights such that $\gamma = \sqrt{\text{Var}[x^{(k)}]}$ and $\beta = \text{E}[x^{(k)}]$, allowing the layer to recover exactly the original identity function ($y = x$).

\subsection{Architectural Placement}
Standard practice dictates inserting the Batch Normalization layer immediately after linear operations (such as Fully Connected layers or Convolutions) and \textbf{immediately before applying the non-linearity} (such as ReLU or tanh).
\begin{keywordbox}
\[ \text{FC / Conv} \longrightarrow \textbf{Batch Normalization} \longrightarrow \text{Activation (e.g., ReLU)} \]
\end{keywordbox}

\subsection{Crucial Difference between Training and Test}
This technique behaves drastically differently between the training phase and the inference phase, an aspect that is often a source of bugs in code:

\begin{itemize}[nosep, leftmargin=*]
    \item \textbf{Training Phase:} The estimates of mean and variance depend entirely on the minibatch of data currently passing through the network.
    \item \textbf{Test Phase:} Since it cannot depend on the statistics of a minibatch (which during testing could be just a single isolated element), the network uses a fixed estimate calculated via a \textit{running average} of the values recorded during training.
\end{itemize}

By using fixed values for mean and variance, BN effectively becomes a simple linear operator. This results in \textbf{zero overhead} during the test phase, as the operation can be mathematically fused into the preceding convolutional or fully connected layer.

\subsection{Overall Benefits}
The introduction of Batch Normalization guarantees:
\begin{itemize}[nosep, leftmargin=*]
    \item Deep networks are much easier to train thanks to a \textbf{better gradient flow}.
    \item The ability to use \textbf{higher learning rates}, leading to faster convergence.
    \item \textbf{Greater robustness} of the network compared to weight initialization methods.
    \item A secondary effect of \textbf{regularization} on the model during the training phase (caused by the noise introduced by the minibatch estimates).
\end{itemize}

\subsection{Alternative Normalization Techniques}
The difference between various normalization methods lies exclusively in the \textbf{dimensions over which they choose to aggregate the data} to calculate the mean ($\mu$) and variance ($\sigma$).

\begin{figure}[htbp]
    \centering
    \includegraphics[width=1\textwidth]{Pictures/normalization_methods.png}
    \caption{Comparison of different normalization methods. The blue blocks indicate the group of values that are aggregated together to compute a single mean and variance.}
    \label{fig:normalization_methods}
\end{figure}

In the three-dimensional cube representation (Figure~\ref{fig:normalization_methods}), the axes represent the data tensors flowing through the network:
\begin{itemize}[nosep, leftmargin=*]
    \item \textbf{N:} The batch dimension (the number of images processed together).
    \item \textbf{C:} The channels (the feature maps, which for instance start as RGB channels).
    \item \textbf{H, W:} The spatial dimensions (Height and Width of the map).
\end{itemize}
The \textbf{blue blocks} indicate the group of values that are taken and ``squashed'' together to compute a single mean and variance. Here is the breakdown of the different methods, their differences, and their use cases:

\subsubsection{Batch Norm (BN)}
\begin{itemize}[nosep, leftmargin=*]
    \item \textbf{Visually:} The blue block spans the entire N axis (the whole batch) and the entire H,W space, but is often restricted to a single slice on the C axis.
    \item \textbf{How it works:} Computes the mean and variance for \textbf{each individual channel}, averaging across \textit{all} images currently in the batch and all spatial pixels.
    \item \textbf{When to use:} It is the standard for classic Convolutional Neural Networks (CNNs).
\end{itemize}

\subsubsection{Layer Norm (LN)}
\begin{itemize}[nosep, leftmargin=*]
    \item \textbf{Visually:} The blue block spans the entire C axis (all channels) and the H,W space, but is often restricted to a single slice on the N axis.
    \item \textbf{How it works:} Computes the mean and variance for \textbf{each individual image}, mixing and aggregating data from \textit{all} its channels and pixels simultaneously.
    \item \textbf{When to use:} Highly recommended for Recurrent Neural Networks (RNNs) and Transformers. Unlike BN, it has the major advantage of maintaining exactly the same mathematical behavior during both training and testing phases.
\end{itemize}

\subsubsection{Instance Norm (IN)}
\begin{itemize}[nosep, leftmargin=*]
    \item \textbf{Visually:} The blue block is very narrow: it takes a single channel (C) of a single image (N), aggregating exclusively along the H,W space.
    \item \textbf{How it works:} Normalizes \textbf{each single channel of each single image} entirely independently and isolated from other channels and images.
    \item \textbf{When to use:} Maintains the same behavior in train and test. Predominantly used in creative or generative tasks, such as texture synthesis and style transfer networks (e.g., making a photo look like a Van Gogh painting).
\end{itemize}

\subsubsection{Group Norm (GN)}
\begin{itemize}[nosep, leftmargin=*]
    \item \textbf{Visually:} The blue block takes a \textbf{limited group of channels} (a portion of the C axis) for a single image (N), aggregating along those channels and the H,W space.
    \item \textbf{How it works:} It serves as a compromise between Layer Norm and Instance Norm. Instead of normalizing across \textit{all} channels together (risking the loss of feature independence like LN) or one channel at a time (like IN), Group Norm divides the channel axis into ``subgroups''. It then computes the mean and variance within each group for every single image independently.
\end{itemize}

\subsection{Motivation: The Problem with Fully Connected Layers}
In a standard Fully Connected (Dense) layer, every input neuron is connected to every output neuron. 
If we process a high-resolution image for example, a \(1000 \times 1000\) RGB image (\(3 \times 10^6\) inputs) even a modest layer with \(10^3\) hidden units would require over 3 billion parameters.

This huge parameter count leads to two main issues:
\begin{itemize}
    \item \textbf{Computational Inefficiency \& Overfitting:} Storing and updating billions of weights requires massive memory and easily leads to severe overfitting.
    \item \textbf{Loss of Spatial Structure:} Flattening a 2D/3D image into a 1D vector completely ignores the grid-like topology of pixels.
\end{itemize}

\subsection{Exploiting Image Structure: Locality and Stationarity}
To overcome these limitations, Convolutional Neural Networks (\textbf{CNN}) build upon two fundamental spatial properties of images:
\begin{enumerate}
    \item \textbf{Local Spatial Correlation:} Nearby pixels are strongly related, whereas distant pixels are less relevant. Instead of connecting a unit to the whole image, we can connect it only to a small local patch (a \emph{receptive field}).
    \item \textbf{Stationarity (Translation Invariance):} Features are location-independent. An edge, texture, or pattern detected in the top-left corner is equally meaningful in the bottom-right corner. Therefore, we can share the same set of weights across all locations.
\end{enumerate}

\subsection{The Core Building Block: A Simple Convolutional Layer}
A Convolutional Layer replaces the dense matrix multiplication with a local, sliding operation.

\begin{itemize}
    \item \textbf{The Kernel (Filter):} A small matrix of learnable weights (e.g., \(3 \times 3\) or \(5 \times 5\)). It acts as a pattern detector.
    \item \textbf{The Sliding Window:} The kernel slides across the input image step-by-step. At each position, it computes an element-wise multiplication with the underlying image patch and sums the results up.
    \item \textbf{The Feature Map:} The output grid produced by sliding the kernel, Figure\ref{fig:featuremap}. High values in the feature map indicate a strong match between the kernel's pattern and that specific image region.
\end{itemize}

\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.7\textwidth]{Pictures/conv_feature_map.png}
    \caption{Illustration of multiple features map obtained by different filters}\label{fig:featuremap}
\end{figure}

\subsection{Key Hyperparameters: Controlling the Convolution}
The behavior and output size of a convolutional layer depend on three primary parameters:
\begin{itemize}
    \item \textbf{Stride (\(S\)):} The step size with which the kernel moves across the image. A stride of 1 moves pixel-by-pixel, while \(S > 1\) downsamples the output.
    \item \textbf{Padding (\(P\)):} Adding zero-valued borders around the input image to preserve spatial dimensions and process edge pixels effectively.
    \item \textbf{Input/Output Channels (\(C\)):} Real images have depth (e.g., \(C_{in} = 3\) for RGB). A kernel must match the depth of the input, resulting in a 3D tensor of shape \((C_{in} \times K_h \times K_w)\). Using \(C_{out}\) distinct kernels produces \(C_{out}\) output feature maps.
\end{itemize}

\subsection{Formal Mathematical Definition}
Mathematically, the operation performed on a 2D input matrix \(I\) by a 2D kernel \(g\) to yield a feature map \(f\) at position \([m, n]\) is defined as:

\begin{equation}
    f[m, n] = (I * g)[m, n] = \sum_{k} \sum_{l} I[m - k, n - l] \, g[k, l]
\end{equation}
\\
where \(k\) and \(l\) iterate over the spatial dimensions of the kernel.

\paragraph{Note on Deep Learning vs. Signal Processing:}
In classic signal processing, the index subtraction \(I[m - k, n - l]\) implies flipping the filter \(g\) by \(180^\circ\). 
\\
However, deep learning frameworks (like PyTorch and TensorFlow) compute \textbf{Cross-Correlation} instead:
\begin{equation}
    f[m, n] = (I \star g)[m, n] = \sum_{k} \sum_{l} I[m + k, n + l] \, g[k, l]
\end{equation}
Skipping the flipping step saves computation. Since kernel weights \(g[k, l]\) are learned from scratch via backpropagation, the network simply learns the pre-flipped weights directly, making the distinction mathematically equivalent for optimization.





\subsection{Intuitive Examples: Classic Image Processing Filters}
Before moving to 3D volumes, let us observe how simple 2D matrices (kernels) process local pixel neighborhoods to extract features or alter images.

\begin{examplebox}
\textbf{2. Vertical Edge Detection Filter:}\\

\begin{examplebox}
\textbf{3. Step-by-Step 2D Convolution Example (Stride 1, Pad 1):}\\
Consider convolving a \(3 \times 3\) image \(I\) with a \(3 \times 3\) vertical edge filter \(g\). Applying \textbf{Padding \(P = 1\)} means we add a border of zeros around \(I\), resulting in a \(5 \times 5\) padded image \(I_{\text{padded}}\):

\[
I_{\text{padded}} =

0 & 0 & 0 & 0 & 0 \\ \hline % chktex 44
\end{array}
\]

Applying the convolution with \textbf{Stride \(S = 1\)} over this padded image gives the output feature map \(f\):
\[
\begin{array}{c} g[k,l] \\ \begin{array}{|c|c|c|} % chktex 44

\textbf{Calculation Detail (Accounting for 180\(^\circ\) Kernel Flip):}\\
According to \(f[m,n] = \sum I[m-k, n-l] g[k,l]\), the kernel \(g\) is flipped by \(180^\circ\) prior to element-wise multiplication:
\[
g_{\text{flipped}} = \begin{array}{|c|c|c|} % chktex 44
\hline % chktex 44

    \[ (1 \cdot 8 - 1 \cdot 2) + (1 \cdot 7 - 1 \cdot 3) + (1 \cdot 9 - 1 \cdot 1) = 6 + 4 + 8 = 18 \]
    
    \item \textbf{Top-Left Value \(f[0,0] = -10\):} Flipped kernel overlaps with the top-left \(3 \times 3\) corner of \(I_{\text{padded}}\):
    \[ (1 \cdot 0 - 1 \cdot 5) + (1 \cdot 0 - 1 \cdot 5) = -10 \]
\end{itemize}

\subsection{Output Shape and Parameter Counting for 3D Volumes}
In practical deep learning architectures, inputs are 3D tensors $(C_{\text{in}} \times H \times W)$ and layers use multiple filters to extract distinct visual features.

\subsubsection*{Spatial Output Size Formula}
Given an input of spatial size $W$, kernel size $K$, padding $P$, and stride $S$, the output dimension $W_{\text{out}}$ is given by:
\begin{equation}
W_{\text{out}} = \left\lfloor \frac{W - K + 2P}{S} \right\rfloor + 1
\end{equation}

\begin{examplebox}
\textbf{Example: Output Volume Size \& Parameters Calculation}\\
If the input volume is a \textbf{$32 \times 32 \times 3$} image, and we apply \textbf{10 filters of size $5 \times 5$} (with Stride $S = 1$, Padding $P = 2$):
\begin{itemize}[nosep, leftmargin=*]
\item \textbf{Output spatial size:} $(32 + 2 \cdot 2 - 5)/1 + 1 = 32$ spatially ($32 \times 32$).
\item \textbf{Output volume size:} $32 \times 32 \times 10$.
\item \textbf{Number of parameters:} Each filter has $5 \times 5 \times 3 + 1 \, (\text{bias}) = 76$ parameters. For 10 filters: $76 \times 10 = \mathbf{760\text{ parameters}}$.
\end{itemize}
\end{examplebox}

\subsection{The Pooling Layer}
A Convolutional Neural Network usually interleaves Convolutional layers with Pooling layers. 

\paragraph{Purpose of Pooling:}
The primary goal of a pooling layer is to perform \textbf{spatial downsampling} (subsampling). By doing so, it:
\begin{itemize}[nosep, leftmargin=*]
    \item \textbf{Reduces the spatial dimensions} (width and height) of the representation, making it smaller and more computationally manageable.
    \item \textbf{Reduces the number of parameters} in the subsequent fully connected layers, thus helping to control overfitting.
    \item \textbf{Provides Translation Invariance:} Small shifts or distortions in the input image will not drastically change the pooled output, making the network more robust to exact feature locations.
\end{itemize}

\paragraph{How it Operates:}
Unlike the convolution layer, a pooling layer \textbf{operates independently on every depth slice} (activation map) of the input. It does not mix channels. If the input has $C$ channels, the output will also have $C$ channels.

\subsubsection*{Max Pooling}
The most common implementation is \textbf{Max Pooling}. Instead of computing a dot product like a filter, it simply slides a window across the image and takes the \textbf{maximum value} within that window.

\begin{examplebox}
\textbf{Max Pooling Example (Stride 2, Filter $2 \times 2$):}\\
Consider a single depth slice (activation map) of size $4 \times 4$. If we apply a Max Pooling layer with a $2 \times 2$ filter and a stride of 2:
\[
\begin{array}{|c|c|c|c|} % chktex 44
\hline % chktex 44
1 & 1 & 2 & 4 \\ \hline % chktex 44
5 & 6 & 7 & 8 \\ \hline % chktex 44
3 & 2 & 1 & 0 \\ \hline % chktex 44
1 & 2 & 3 & 4 \\ \hline % chktex 44
\end{array}
\quad \xrightarrow{\text{Max Pool } 2 \times 2, S=2} \quad
\begin{array}{|c|c|} % chktex 44
\hline % chktex 44
6 & 8 \\ \hline % chktex 44
3 & 4 \\ \hline % chktex 44
\end{array}
\]
The spatial dimensions are exactly halved. The operation discards $75\%$ of the activations, keeping only the most prominent features (highest numbers) in each local $2 \times 2$ region.
\end{examplebox}

\section{Transfer Learning}

\subsection{The Fundamental Concept (Why use it?)}
Convolutional Neural Networks (CNNs) require a massive amount of data to be trained from scratch effectively. If your target dataset is small (e.g., less than 1 million images), training a deep architecture from scratch would inevitably lead to severe overfitting.
The standard solution is \textbf{Transfer Learning}: taking a ``Source'' model that has already been trained on a gigantic dataset (e.g., ImageNet, which contains millions of images across thousands of categories) and ``transferring'' the learned knowledge to a ``Target'' model applied to your specific, smaller dataset (e.g., CIFAR-10 or a custom medical imaging dataset).

\subsection{Practical Implementation (The Mechanism)}
Taking a standard network like VGG-11 as an example, the transfer learning procedure generally involves two main steps:

\begin{itemize}[leftmargin=*]
    \item \textbf{1. Keeping the Convolutional Layers (Feature Extractors):} The early and middle layers of the pre-trained network are preserved intact. Their purpose is to act as \textit{feature extractors}. Since the network has already learned to recognize lines, edges, textures, and complex shapes from the source dataset, these visual characteristics are treated as ``universal'' and highly useful for almost any downstream visual task.
    \item \textbf{2. Replacing the Classifier:} The final layers of the network (the Fully Connected or ``classifier'' layers) are removed. In their place, a new set of Fully Connected layers is appended. Only these new layers (and optionally a few of the deeper convolutional layers) are trained specifically to classify the categories of the new target dataset.
\end{itemize}

\subsection{Pervasiveness: The Norm, Not the Exception}
Transfer Learning is ubiquitous and is considered the absolute standard in modern deep learning development. Its applications extend far beyond simple image classification:
\begin{itemize}[leftmargin=*]
    \item \textbf{Object Detection:} Advanced architectures like Fast R-CNN utilize a CNN pre-trained on ImageNet as a foundational backbone to extract features from the entire image before predicting bounding boxes.
    \item \textbf{Image Captioning:} A pre-trained CNN is often fused with a Recurrent Neural Network (RNN) or Transformer, where the CNN provides the rich visual feature embeddings necessary for the text generation model.
\end{itemize}

\begin{keywordbox}
\textbf{The ``Model Zoo''} \\
In practice, you do not need supercomputers or months of computation time to train the initial source model. All major Deep Learning frameworks (such as PyTorch and TensorFlow) provide a \textbf{Model Zoo} (e.g., \texttt{torchvision.models} in PyTorch). 

These libraries host the pre-trained weights of famous state-of-the-art architectures (VGG, ResNet, DenseNet, etc.) trained by large research institutions. They are ready to be downloaded with a single line of code and adapted via transfer learning to your specific task.
\end{keywordbox}
